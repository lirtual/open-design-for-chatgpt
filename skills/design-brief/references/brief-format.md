# Compact design brief output

Use these headings in a deliverable; omit fields truly irrelevant to the task.

1. **Purpose / audience:** who will use the interface and what they need to accomplish.
2. **Scope:** screens or sections, key actions, essential content, platform.
3. **Visual direction:** mood, palette roles, typography, spacing/density, imagery restrictions.
4. **Constraints:** existing DESIGN.md/components/framework, responsive sizes, accessibility, privacy.
5. **States:** loading, empty, error, populated, long-content/edge; for forms include validation and submit-pending.
6. **Acceptance:** checkable outcomes, plus specific measurements only if actually measured.
7. **Assumptions / unavailable evidence:** separate user decisions from estimates.

A brief is not automatically a DESIGN.md. If explicitly asked for both, produce both while respecting existing project files.
